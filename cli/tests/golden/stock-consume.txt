usage: kyokki stock consume [-h] [--location {main_fridge,freezer,pantry}]
                            [--allow-partial] [--dry-run]
                            [--idempotency-key KEY] [--url URL]
                            [--token TOKEN] [--json] [--verbose]
                            NAME AMOUNT UNIT

Consume AMOUNT UNIT of a product, taking from the item that expires
first. NAME must match a product name exactly (any case); otherwise
the candidates are printed and the exit code is 4. A NAME that is a
UUID is sent as the product id.

positional arguments:
  NAME                  product name, or product id
  AMOUNT                how much, in UNIT (a number above 0)
  UNIT                  dl, tsp, tbsp, g, pcs (l, ml, kg and the like are
                        converted by the server)

options:
  -h, --help            show this help message and exit
  --location {main_fridge,freezer,pantry}
                        only items in this location
  --allow-partial       consume what there is instead of failing on short
                        stock (exit 5)
  --dry-run             show what would be consumed; change nothing (no
                        Idempotency-Key)
  --idempotency-key KEY
                        retry key (at most 255 characters); default: SHA-256
                        of this command line and the UTC minute, so a retry
                        within the minute is safe

connection and output:
  --url URL             Kyokki base URL, e.g. http://kyokki.lan:8000 (default:
                        $KYOKKI_URL)
  --token TOKEN         API token, sent as a Bearer header and never printed
                        (default: $KYOKKI_TOKEN)
  --json                print the API's JSON (the default when stdout is not a
                        terminal)
  --verbose             log each request and its status to stderr

examples:
  kyokki stock consume milk 2 dl
  kyokki stock consume 'minced beef' 0.4 kg --location freezer
  kyokki stock consume eggs 3 pcs --dry-run

exit codes:
  0 ok
  1 error: unreachable, server error (5xx) or an unexpected answer
  2 usage: bad arguments, or the API rejected the request (400 invalid, 422)
  3 not found
  4 ambiguous name: the candidates are printed on stdout
  5 insufficient stock
  6 conflict: the name belongs to another product, or a reused Idempotency-Key
  7 auth: missing or unknown token (401), or a read token on a write (403)
