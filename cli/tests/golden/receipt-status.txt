usage: kyokki receipt status [-h] [--url URL] [--token TOKEN] [--json]
                             [--verbose]
                             ID

Status of receipt ID, and once it has been read, its lines: index,
printed name, generic name, the matched product (and whether verified),
quantity and unit, and whether it is non-food.

positional arguments:
  ID             the receipt's id (a UUID), from receipt upload

options:
  -h, --help     show this help message and exit

connection and output:
  --url URL      Kyokki base URL, e.g. http://kyokki.lan:17300 (default:
                 $KYOKKI_URL)
  --token TOKEN  API token, sent as a Bearer header and never printed
                 (default: $KYOKKI_TOKEN)
  --json         print JSON: the API's answer, or an error's detail object
                 (the default when stdout is not a terminal)
  --verbose      log each request and its status to stderr

examples:
  kyokki receipt status 0b6f7a3e-8d4c-4a53-9d1e-2f6c1b7e9a01
  kyokki receipt status 0b6f7a3e-8d4c-4a53-9d1e-2f6c1b7e9a01 --json

exit codes:
  0 ok
  1 error: cannot reach the server, a 5xx, an answer that is not JSON
  2 usage: bad arguments, or the API rejected the request (400 invalid, 422)
  3 not found: no receipt has the ID
  4 ambiguous name: does not occur for this command
  5 insufficient stock: does not occur for this command
  6 conflict: does not occur for this command
  7 auth: missing or unknown token (401), or a read token on a write (403)
